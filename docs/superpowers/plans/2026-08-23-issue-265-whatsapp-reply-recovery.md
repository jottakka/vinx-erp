# Issue #265 WhatsApp Reply Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Ensure each durable inbound WhatsApp row causes at most one automated Meta reply POST, even when the process stops after provider acceptance and before local completion.

**Architecture:** Add a reply_in_flight state to the existing inbound row and commit that barrier immediately before the provider POST. Redelivery cannot reclaim an in-flight row; known completion persists the wamid, while uncertain outcomes remain terminal/manual rather than being resent.

**Tech Stack:** .NET 10, PostgreSQL SECURITY DEFINER functions, Wolverine durable inbox, IHttpClientFactory, xUnit/Testcontainers.
